# AGENTS.md

This file provides guidance to AI coding agents working in this repository. It is read before every task, so it is deliberately slow-moving: it holds the commands, the layout, the conventions and the invariants. Status — what is fixed, what is still open — lives in [TODO.md](TODO.md), not here.

## Overview

Event-driven AI surveillance system built on GStreamer, SRT, LibreYOLO, MongoDB, SQLite3 and RabbitMQ. One Go module holding five services, plus a Python "nodes" runtime, all communicating over a RabbitMQ topic exchange.

Deep-dive docs: [ARCHITECTURE.md](ARCHITECTURE.md) (services, data flow, protocol, storage), [DESIGN.md](DESIGN.md) (rationale, trade-offs, invariants), [DEPLOYMENT.md](DEPLOYMENT.md) (installing and running it without containers) and [TODO.md](TODO.md) (staged execution tracker and fix status). Consult them before non-trivial changes.

## Commands

```sh
make lint          # golangci-lint the module (config: .golangci.yml at repo root)
make test          # test-go + test-nodes
make test-go       # go test ./... (no python needed; this is what CI runs)
make test-nodes    # python tests for nodes/lib/core (nodes/tests; needs ./.venv)
make typecheck     # pyright over nodes/ (config: ./pyproject.toml; needs ./.venv)
make build         # build every cmd/ entrypoint into bin/surr-<name>
make               # lint + test + typecheck + build
make clean         # remove .cache/ and bin/

# One binary / one service's packages
make build-tx      # also: build-rx, build-hub, build-subscriptions, build-analytics
make test-hub      # also: test-rx, test-subscriptions, test-tx, test-analytics

# Cut a release: gates, then one annotated tag, then push
./scripts/release.sh v0.3.0

# Install a released binary without a checkout
go install github.com/booleanism/surr/hub/cmd/hub@v0.3.0

# Build a release binary (stripped, trimpath)
make build-tx RELEASE_TYPE=release

# Assert what `ps` cannot show: a client error is a client error, a node registers
# and declares its queries, tx -> rx -> node carries frames into MongoDB, the
# report carries the declared queries, a stopped node is refused, and tx exits 0
# on SIGTERM. Starts RabbitMQ/MongoDB if they are not already up.
./smoke.sh

# Run a single service (each is a urfave/cli v3 app; see its cmd/<name>/cmdline.go for flags)
go run ./hub/cmd/hub run --help

# Python node (from the repo root; uv sync creates .venv/)
uv sync
uv run python nodes/bustle.py --help
```

Knobs: `RELEASE_TYPE=release` (adds `-s -w -trimpath`), `TAGS` (build tags), `GOFLAGS`, `LDFLAGS`, `VERSION`, `TESTFLAGS` (e.g. `-race`, `-count=1`), `NODESTESTFLAGS`, `PYTHON`, `PYRIGHT`, `TYPECHECKFLAGS`.

`VERSION` defaults to `git describe --tags --always --dirty` and is injected into every binary with `-X main.Version`, so `--version` and the `version=` field on every log line report the build. `LDFLAGS` appends to it rather than replacing it. A binary built without that injection — `go install ...@vX.Y.Z`, or a bare `go build` — falls back to `internal/buildinfo.Resolve`, which reads the module version the toolchain recorded and then the stamped VCS revision, so no path reports "dev" when an identity exists. The Python node resolves the same string independently (`nodes/lib/version.py`), which is what makes a mixed deployment's two build ids comparable. Do not reintroduce a hand-written version constant: the point of the injection is that no constant has to be kept in sync by hand.

`go install` is deliberately unsupported: the `replace` directives a published module cannot resolve are the same ones that keep a local `internal/` edit visible to a service build. Build from a checkout — `make build` — and stamp `VERSION` if you need the binaries to name a release rather than a commit.

CI is `.github/workflows/ci.yml`: `make lint`, `make test-go` and `make build` on one runner, `make test-nodes` and `make typecheck` on another (PyGObject built from source). `make test` is the two halves combined.

The Go job runs inside a `golang:1.27.1-trixie` container rather than directly on the runner, and both halves of that image tag are load-bearing:

- **The distro, because `tx` links go-gst.** `go-gst v0.0.2` references `C.GstIdStr`, which GStreamer only added in **1.26**. The `ubuntu-24.04` runner image ships 1.24, so on the bare runner `tx` does not type-check (`could not determine what C.GstIdStr refers to`, then 15 cascading `Add`/`AddPad`/`GetStaticPad` errors) and `make lint` fails on the first package it reaches. trixie is GStreamer 1.26.2, which clears that floor with room to spare.
- **The patch version, because golangci-lint has a ceiling.** golangci-lint v2.13.2 is built with Go 1.27.0 and cannot read the export data Go 1.27.2 emits (`cannot decode "internal/goarch", export data version 5 is greater than maximum supported version 4`), so `golang:1.27-trixie` (1.27.2) fails and `golang:1.27.1-trixie` passes. 1.27.1 is also the highest `go` directive in the repo (rx and tx), so it is the floor, not a downgrade.

The Python job stays on the runner: PyGObject 3.58 builds from source and needs GLib >= 2.80, which ubuntu-24.04 satisfies. It has been green.

The Go job's first step after checkout is `git config --global --add safe.directory "$GITHUB_WORKSPACE"`, and it is not optional. A container job runs as root while the workspace it mounts is owned by the runner's user, and git >= 2.35.2 refuses a repository it does not own (`fatal: detected dubious ownership in repository at '/__w/surr/surr'`, exit 128). `go build` runs `git status` to stamp VCS information into every binary, so without that line the build dies with `error obtaining VCS status: exit status 128` — and the Makefile's own `git describe` for `VERSION` fails the same way. This cannot be reproduced on a developer machine that runs rootless Docker: the host user is mapped to uid 0 inside the container, so the checkout *is* root-owned and git never complains. Only real-root Docker, which is what Actions uses, reproduces it.

`make build-<name>` builds the `cmd/<name>/` package that contains `main.go` and writes `bin/surr-<name>`. `make test` covers every package in the module, so a failure anywhere fails the target. `make test-nodes` uses `./.venv/bin/python` when it exists (`PYTHON=...` overrides) and fails with instructions when that interpreter cannot import `aio_pika`/`numpy`.

`make typecheck` runs pyright from the repo root against `./pyproject.toml`. `venvPath`/`venv` in that file are load-bearing — pyright does not pick the venv up merely because it was launched from the venv's own `bin/` — and so is `extraPaths = ["nodes"]`, which is what resolves the nodes' `from lib.core import ...` imports from a config file that lives one level above them. `typeCheckingMode = "standard"` is the level the runtime is actually held to. The gate is in `make` but deliberately not in `lint`/`test`, which stay usable on a Go-only checkout.

The Python side is a uv project: `./pyproject.toml` declares the dependencies (pinned exactly, with the torch CPU index wired up through `[tool.uv.sources]`) and `./uv.lock` pins the full transitive graph. The venv is `./.venv` — at the repo root, not in `nodes/` — while all the node code stays in `nodes/`. `[tool.uv] package = false` is what lets `uv sync` install the dependencies without trying to build the project, since `nodes/` is a directory of scripts rather than an importable package.

The repository is **one Go module**: `github.com/booleanism/surr` at the root, with the five services as directories (`hub/`, `rx/`, `tx/`, `subscriptions/`, `analytics/`) and the shared packages under `internal/`. `go build ./...` at the root covers all 37 packages, and `go list ./...` is the whole tree.

It used to be six modules tied together by a committed `go.work` plus five `replace github.com/booleanism/surr => ../` directives. That shape could not be installed: `go install path@version` refuses a module whose `go.mod` carries a `replace`, and a service module could not resolve the shared one from the proxy without one. Collapsing to a single module removed both the replaces and the cross-module requirement that would have needed pinning, so `go install github.com/booleanism/surr/hub/cmd/hub@v0.3.0` works with no `go.work` and no ceremony. The cost is that the service module paths moved: `github.com/booleanism/surr/hub` used to name a module and now names a directory, which is why the import paths are unchanged but the `require` lines are gone. Do not reintroduce a second `go.mod` below the root without re-reading this paragraph — it silently restores the uninstallable shape.

A binary installed from a version suffix gets no `-ldflags`, so `main.Version` keeps its `"dev"` default; `internal/buildinfo.Resolve` recovers the version from the binary's own module metadata (`go version -m` shows `mod github.com/booleanism/surr v0.3.0`) and falls back to the stamped VCS revision for a bare `go build`. `make build` still injects `git describe` with `-X` and that value wins, because it is the only source that can say "dirty".

## Architecture

### Services and data flow

```
camera (RTSP) → tx ──SRT──→ rx ──SRT──→ nodes (Python, DEIM) ──→ MongoDB
                                ↑____________ RabbitMQ ____________↓
                    hub (HTTP API, auth)   subscriptions (SQLite)   analytics
```

- **tx** (`tx/`): standalone transmitter. Pulls an RTSP source, transcodes via GStreamer (go-gst), publishes SRT (`srt://host:port?mode=caller&streamid=publish:<subscription id>`) and/or records. Also has a DASH `serve` command. `tx run` requires a `tx serve` DASH server to already be listening, because it registers the stream over HTTP at startup and aborts otherwise.
- **rx** (`rx/`): receiver/relay. Terminates SRT ingress (where tx publishes), exposes SRT egress that nodes pull frames from. Talks to the broker to look up which nodes are subscribed.
- **hub** (`hub/`): control plane. HTTP API (JWT auth w/ argon2, users, nodes, subscriptions handlers) backed by SQLite, plus RabbitMQ handlers.
- **subscriptions** (`subscriptions/`): SQLite-backed service answering which nodes belong to a subscription (e.g. the `subscriptions.nodes.get` command).
- **analytics** (`analytics/`): the read path over MongoDB. It keeps a SQLite registry of the aggregation queries each node declared about its own documents (`analytics.declare`, `analytics.queries.list`) and runs one of them on request (`analytics.query`). A caller names a declared query and passes parameters; it never supplies a pipeline, so the aggregation surface stays the node's to define and this service's to bound. It is the read path for `GET /nodes/analytics`: the hub asks the service what a node declared and runs that list, so the charts belong to the node type and a new detector with a different story to tell needs no hub change.
- **nodes** (`nodes/`): Python workers. `nodes/lib/core/node.py` is the node runtime and `bustle.py` is the object counter (object detection via LibreYOLO): a GStreamer pipeline (`nodes/lib/core/pipeline.py`) pulls SRT frames, the detector counts chosen classes, results are stored in MongoDB and served back over the broker. The detector sits behind a narrow `Detector` Protocol in `nodes/lib/detector.py` (`detect(frame) -> list[Detection]`) whose only implementation loads LibreYOLO's `LibreDEIMm.pt`; keep it that way — nothing outside that file may import `libreyolo` or touch torch types. Long-running: SIGTERM/SIGINT trigger a graceful path that stops workers, deregisters the node from the hub (`nodes.remove`), then closes the broker connection. That path lives in `nodes/lib/core/node.py`, not in the node type: `Node` owns the router, the introduce ticker, `nodes.add`/`nodes.remove` and the shutdown ordering, and a node type supplies a `Worker` (`attach` handlers, `start` background tasks, `registered` post-registration hook, `stop`). `bustle.py` is therefore only argument parsing, storage setup and the `BustleWorker`. Do not put broker lifecycle in a node type — a second type would copy it, and the ordering it encodes (stop the frame source → cancel tasks keeping the listener alive → `nodes.remove` → cancel the listener) fails silently when it is wrong. Logging is stdlib `logging` configured by `nodes/lib/core/logging_setup.py`. `nodes/` is not a package (no `nodes/__init__.py`): the imports are `from lib.core import ...` / `from lib.bustle import ...` with `nodes/` as the root, and Python puts a script's own directory on `sys.path`, so `uv run python nodes/bustle.py` from the repo root resolves them as-is. The dependencies and the pyright configuration live in the root `./pyproject.toml`, and the venv is the root `./.venv`.

### Sibling discovery protocol (the core pattern)

All services implement the same "sibling" RPC protocol over a shared RabbitMQ topic exchange (Go side: `internal/protocols/rabbitmq/router.go`; Python mirror: `nodes/lib/core/router.py`):

1. On startup, each service declares the topic exchange, an exclusive auto-delete queue bound to `rpc.direct.<name>` and `rpc.broadcast`.
2. It broadcasts an `introduce` message (every 1s) advertising its available commands. Peers store these in their siblings registry keyed by routing key (`internal/protocols/siblings.go`, `nodes/lib/core/siblings.py`), so `GetName(command)` resolves which sibling can serve a command.
3. The same message carries `ProtocolRevision` and the sender's build id. A peer on a different revision is logged as a warning and still registered — a mismatch must be diagnosable, not fatal, so it is on the record before it surfaces as an unexplained failure on some later command. `internal/protocols/siblings.go` holds the number and the bump rule; `nodes/lib/core/siblings.py` mirrors both and must be changed in the same commit.
4. Requests are published with a UUID `CorrelationId` (trackID) and `ReplyTo`; responses come back on the caller's direct routing key and are matched via a pending-trackID map. Python serializes `RouterResponse` with base64-encoded bytes in a JSON string; a Go caller that wants those bytes declares a `[]byte` target and lets encoding/json do the decode.

Commands are conventionally named `<subject>.<verb>` — node commands embed the node ID: `<node-id>.sink.start`, `<node-id>.sink.stop` (see `nodes/lib/bustle/handlers.py`, `rx/internal/adapter/rabbitmq/nodes.go`). Full command catalog: ARCHITECTURE.md.

### Node registration

Python nodes self-register in the hub's `nodes` table: `nodes.add` on boot (retried until the hub introduces itself) and `nodes.remove` on graceful shutdown. The hub serves both commands (`hub/internal/protocols/rabbitmq/handlers/node.go`) with an idempotent upsert (`ON CONFLICT(id) DO UPDATE` in `hub/internal/db/sqlite/node.go`) so re-registration on restart is safe. On the node side, `nodes/lib/core/rpc.py` provides `call()` — resolve the sibling serving a command, send, await reply with timeout/retries; it tries every candidate sibling. Registration is once-per-run: a hub database reset while a node keeps running requires restarting the node (or switching to periodic re-send). A SIGKILL'd node leaves a stale row in that table, but no longer a stale *sibling*: both registries expire an entry `SiblingTTL` (15s) after the last `introduce` that carried it, checked lazily on lookup, so a dead node stops being resolvable fifteen missed broadcasts later instead of never. Before that expiry existed, `GetName` kept naming the dead peer and every dispatch spent a full 5s `sinkCommandTimeout` before the sink was treated as unavailable; now it fails at once, which is what lets `rx` cycle at the same rate whether a node was registered and died or never registered at all. The row itself is never deleted — `nodes.add` carries no timestamp, so it cannot be dated — and that is fine: liveness is read from the sibling registry instead (next section).

### Shared root packages (imported by hub, rx, subscriptions, analytics, tx)

- `internal/protocols/` — Command/HandlerFunc/Router types, the handlers registry, sibling model
- `internal/protocols/rabbitmq/` — the router (exchange/queue setup, introduce, Send/Recv, delivery dispatch)
- `internal/pools/` — sync.Pool-based object pools (bytes, goroutines/task running, sibling-name slices, nodes, subscriptions); always `Get()` from a pool and `Put()` it back rather than allocating
- `internal/models/` — Node, User, Subscription, SRT and analytics models shared across services, plus the sentinels that cross layers (`ErrUserExists`, `ErrNodeAlreadySubscribed`, `ErrQueryTooLarge`, `ErrDeclarationNotFound`)
- `internal/db/` — `Transaction`, `TXFactory`, `VerifySchema`, the embedded migration runner (`migrate.go`), and the build-tagged `dialect` seam that chooses its engine
- `internal/logging/` — zerolog setup (`Setup`, `RedactURL`) and the `Cleanups` registry
- `internal/backoff/` — exponential backoff with deterministic jitter, used by every restart loop
- `internal/restart/` — `restart.Loop(ctx, name, f)`, the one wrapper every long-running routine runs inside

### Per-module layout

hub, subscriptions and analytics follow the same layering: `cmd/<svc>/` (CLI + main wiring) → `internal/protocols/` (transport handlers: http/rabbitmq) → `internal/usecases/` (business logic) → `internal/db/sqlite/` (storage) with `internal/adapter/` bridging usecases to the router. analytics also has `internal/db/mongo/` for the aggregation it runs. rx is similar minus the DB. tx is its own world: `internal/src` (GStreamer sources), `internal/sink` (srt/dash/etc sinks), `internal/streaming`, `internal/core` (coder/muxer/pipeline), `internal/server/dash`.

Top level: `internal/` holds the shared packages (protocols, pools, models, db, logging, restart, buildinfo) that the five services import; `nodes/` is the Python runtime (`nodes/lib/core` is the type-agnostic runtime, `nodes/lib/<type>` the worker); `.github/workflows/ci.yml` is CI. Wiring is configuration, not code: each service is a standalone binary with its own flags (broker URL, database path, listen address), so the deployment that connects them lives wherever it is operated, not here.

### Conventions

- **Resource cleanup**: Go services use `*logging.Cleanups` (`internal/logging/cleanups.go`) — `cleanups.Register(func() error {...})` where the resource is created, `Run()` drains them on context cancellation in registration order. Registration is safe at any time, including while the drain is running.
- **Long-running routines**: wrap every blocking routine in `restart.Loop(ctx, name, f)` (`internal/restart/`). It re-enters `f` after an exponentially growing, jittered delay (`internal/backoff/`) instead of spinning, logs each failure, and returns once ctx is cancelled. A broker connection that drops is handled by `rabbitmq.Supervisor.Watch`, which redials, re-declares the queue and installs it with `router.ReplaceChannel` — the router reads its channel through `channel()`/`queue()` accessors, so publishes and consumes always use the current one.
- **SQLite schema**: the services never create their own tables, and never migrate implicitly. Migrations live in `<svc>/internal/migrations/sqlite/` (golang-migrate naming, so the tables and `schema_migrations` stay readable by either tool), are compiled in via `<svc>/internal/migrations/embed.go`, and are applied by that service's own `migrate` subcommand (`./bin/surr-hub migrate -d ./hub.db up`, leaf mode `up`/`down`/`status`, `-d/--database` accepted on either side of the mode). `hub`, `subscriptions` and `analytics` call `db.VerifySchema(ctx, sqlDB, migrateHint, tables...)` right after opening the connection and exit with one actionable error when a table is missing. `migrate` exits non-zero on failure while `run` exits 0 on a clean shutdown, so each `cmd/<svc>/main.go` is `func main() { os.Exit(mainEntry()) }` — `os.Exit` skips deferred calls, and the deferred cancellation is what lets the cleanup hooks run.
- **The migration runner names its engine at build time, not at run time.** `internal/db/migrate.go` is engine-agnostic; `internal/db/dialect_sqlite.go` (behind `//go:build !postgres`) supplies the five things that are not portable — the driver name, the version-table DDL (`version uint64` is not a Postgres type), `PRAGMA busy_timeout` + `BEGIN IMMEDIATE`, whether the driver accepts a multi-statement `Exec`, whether DDL is transactional, and the bind placeholder. `dialectFor()` is the single dispatch point, and the same build tag selects the embedded migrations package. `internal/db` therefore links `mattn/go-sqlite3` itself: the root module now needs cgo, and the driver is no longer registered by a blank import three layers away in some `main`. Adding a second engine means a second `dialect_<engine>.go` plus that engine's migrations package — not a flag.
- CLI parsing is hand-rolled on top of urfave/cli v3 into a `CommandLine` struct in `cmd/<svc>/cmdline.go`; new flags go there.
- New broker commands: register a handler on the serving side (`handlers.Set`), which automatically advertises it in `introduce`; callers resolve the sibling via the siblings registry before `Send`/`Recv`.
- **Logging**: zerolog on the Go side via the shared `internal/logging` package — root logger injected into ctx at `main`, packages read `zerolog.Ctx(ctx)`; console writer default, JSON opt-in via `--log-format`; canonical snake_case fields (`command`, `track_id`, `sub_id`, `node_id`, `peer`, ...). Never log passwords, tokens, the JWT secret, credential-bearing URIs (log `scheme://host` via `logging.RedactURL`), or full RPC/request payloads (length at debug). Python nodes stay on stdlib `logging` (`nodes/lib/core/logging_setup.py`). See DESIGN.md §13.
- Python nodes mirror the Go protocol exactly (routing keys, introduce, RouterResponse shape) — changes must stay in sync across `nodes/lib/core/` and `internal/protocols/`.

### Invariants (do not break)

The `E`-numbered items in TODO.md section E are the historical record of how each of these was violated. The rules are what matter; none of them depend on the story.

- **UUID storage class must stay BLOB.** SQLite compares by storage class, so an insert binding TEXT against a lookup binding BLOB matches zero rows *silently*. Every bind is `id[:]`; keep it that way.
- **Replies go through `protocols.ResultResponse`/`ErrorResponse`.** `RouterResponse.Result` is `json.RawMessage`, so a raw `[]byte(err.Error())` cannot marshal and the failure is silently dropped. The `-1/-2/-3` codes are named constants (`CodeDecodePayload`, `CodeDomain`, `CodeMarshalReply`) and are part of the wire protocol — `nodes/lib/core/handlers.py` mirrors them.
- **Read a failure with `ErrorMessage()`; read a payload by unmarshalling `Result` into the type you asked for.** There is deliberately no `GetBytes()`-style helper. A short ASCII failure message such as `internal` is itself valid base64, so any decoder that "tries base64 and falls back to text" returns garbage for exactly the replies it is most likely to be called on; the helper was deleted rather than made clever. A `[]byte` target is what makes encoding/json base64-decode a Python node's bytes result.
- **Request bodies decode into `handlers.credentials`, never into `models.User`.** `models.User.Passwd` is `json:"-"`, so a whole-`User` marshal — which `hub/internal/adapter/rabbitmq/subscription.go` does, to send the `subscriptions.nodes.by.user.get` payload — cannot carry the argon2id hash. Signup and signin use `decodeCredentials`, which sets `DisallowUnknownFields` (so `password` is a 400 rather than a silently empty account) and requires both fields; a duplicate email is `models.ErrUserExists` → 409, matched on SQLite's *extended* constraint code because `SQLITE_CONSTRAINT` also covers NOT NULL, CHECK and foreign keys.
- **A node's liveness comes from the sibling registry, never from the `nodes` table.** `nodes.add` is sent once per run and carries no timestamp, so a row left behind by a node killed without a graceful `nodes.remove` cannot be told apart from a live one — the dead rows accumulate by design, because a node that comes back with a new id adds a row rather than replacing one. `LiveNodeIDs`/`NodeAlive` (`internal/protocols/siblings.go`) answer the question from the introduce stream instead: a node's commands embed its id (`<node-id>.sink.start`) and are re-broadcast every second, and both accessors go through the same `SiblingTTL` check `GetName` uses, because two answers to "is this peer alive" would show up as a node that is offered and then unreachable. Both user-visible consequences are load-bearing: `/nodes/availability` offers a row only when the node is live, and `/nodes/analytics` answers 409 (`models.ErrNodeUnavailable`) for one that is not, since a declaration outlives its node and would otherwise return every query's empty shape — a report that reads as "this node saw nothing".
- **Every RPC registers a trackID and must release it.** `router.Recv` does `defer r.Forget(trackID)`; adapters do the same after `Send`. The reply channel is buffered (cap 1) so a late reply is dropped and Nacked rather than blocking the delivery path.
- **A pool-dispatched RPC must hand its outcome back over a channel.** `pools.RunTask.Run` only enqueues the task and returns nil — it never reports what the task did. So `Run(ctx, func() { if err := roundTrip(); err != nil { return } })` returns nil on *every* path, and a caller that trusts it reports success for a node that never answered. `rx/internal/adapter/rabbitmq/nodes.go` `do()` and `hub/internal/adapter/rabbitmq/subscription.go` `call()` both send the result over a `make(chan error, 1)` and wait for it; the buffer is what stops a reply arriving after the caller gave up from blocking a pool worker. The RPC carries its own `context.WithTimeout` for the same reason: without one, `router.Recv` parks on `ctx.Done()` until the *process* context ends, retiring a pool worker per stale dispatch (`rx` has `--worker 28` of them).
- **A non-zero reply code is a failure, not a note.** Both adapters turn `resp.Code != protocols.CodeSuccess` into an error, because a node that refuses a command (`invalid source address`) must not look like a started sink. Add a code to `internal/protocols/handlers.go` and map it in the adapter when a new class of failure has to reach HTTP — `CodeConflict` (`-5`) is what makes `POST /subscriptions/add` answer 409 instead of 500 for a node that is already subscribed. The codes are part of the wire protocol: `nodes/lib/core/handlers.py` mirrors them.
- **`analytics.query` takes a query NAME, never a pipeline.** The aggregation belongs to the node that wrote the documents; the bounds belong to the service. Those bounds live in `analytics/internal/usecases/query.go` and are an **allowlist** of read-only stages, not a blocklist — `$facet` can nest a writing stage (`$out`, `$merge`) inside a pipeline that looks read-only from outside, so a blocklist loses and the contents of a `$facet` are validated recursively. Do not add `$out`/`$merge`/`$unionWith`/`$lookup`/`$graphLookup` to `allowedStages`, and do not merge the appended `$limit` into a manifest's own `$limit` — appending is what stops a manifest without one from returning a whole collection. Parameter substitution works on the pipeline's raw bytes on purpose: decoding into a Go map would lose `$sort` operand order, which changes what the query means.
- **A declaration is a set, and a re-declare replaces it whole.** `UpsertDeclaration` (`analytics/internal/db/sqlite/declaration.go`) is delete-then-insert inside one transaction, because a node owns its manifest entirely: a re-declare that drops a query has to remove it, or the registry keeps offering a query the node no longer serves. The manifest is validated at **declare** time so a broken pipeline is refused where the author can still fix it, and again at **query** time because the registry is not the only way a manifest could have arrived.
- **Blocking SRT calls are not cancellable by themselves.** `rx/internal/protocols/srt/listen.go` closes the socket on ctx cancellation because that is the only thing that wakes `srt_epoll_wait`; do not call `sock.Listen`/`Accept` directly from a routine. The same applies to an established stream: a bare `sock.Read`/`sock.Write` in a loop never returns on cancellation, so both loops arm a deadline per iteration (1s idle for reads, 10s for writes) and treat a `net.Error` timeout as a tick. This works only because `srtgo` sockets are created non-blocking — a blocking socket ignores the deadline.
- **The SRT fan-out is reference-counted and the registry owns the close.** `broadcaster.Publish` hands one pooled buffer to every subscriber with `refs` set to the subscriber count; each `Chunk.release()` returns it to the pool exactly once. `Subscribe` returns a `*subscription` handle and only `Unsubscribe(handle)` may close a channel — it refuses a handle that is no longer registered, which is what stops a replaced subscriber's deferred call from closing its successor's channel. Never close a subscriber channel anywhere else.
- **The database engine is a build-time choice, so both dialect build tags must compile.** `internal/db/dialect_sqlite.go` carries `//go:build !postgres` and the three services' `internal/migrations/embed.go` carry the same tag, so exactly one dialect and one set of embedded SQL are compiled into a binary and there is no runtime switch to get wrong. Nothing outside `dialect_sqlite.go` may name a driver, a `PRAGMA`, a bind variable or `BEGIN IMMEDIATE` — a hardcoded `?` is a runtime error on Postgres, not a compile error. `-tags postgres` currently fails with `build constraints exclude all Go files in .../internal/migrations`, which is the intended signal: a Postgres build has to supply its own migrations package.
- **Both tx encoder build tags must compile.** The `va` and default variants of `encElementWithOptions` must keep the same signature (`bitrate uint32`); `make lint` and `make build` do not pass build tags, so check the `va` variant explicitly with `make test TAGS=va` (or `cd tx && go build -tags va ./... && go vet -tags va ./...`).
- **Never hardcode a GStreamer element name that may not be installed.** `gst.ElementFactoryMake` returns nil for a factory the distribution does not ship, and the first `Add`/`Link`/`GetStaticPad` through it is a SIGSEGV, not an error. Go through `pickElement` (`tx/internal/core/coder/element.go`) with a preference list, check `Valid()`, and report what was missing. The concrete trap: `fdkaacdec`/`fdkaacenc` exist only where the non-free fdk-aac was built in, so a developer machine with deb-multimedia has them and a stock Debian image does not.
- **`tx run` never brings its pipelines to NULL.** The shutdown path deliberately leaves them in PLAYING and exits after `loop.Run()` returns, because the NULL transition disposes the RTSP source and races GIO's threaded resolver on GLib 2.84 (`g_assert (g_cancellable_is_cancelled (cancellable))` in `gio/gthreadedresolver.c`, which segfaults on a clean SIGTERM as much as on an unreachable source). Re-adding `SetState(gst.StateNull)` — from the loop thread or from a cleanup hook — reintroduces the crash. The accepted cost is that an interrupted `--recording` needs remuxing, and `runFailure` is what turns a bus error into a non-zero exit.
- **`ProtocolRevision` is mirrored in two languages.** `internal/protocols/siblings.go` and `nodes/lib/core/siblings.py` hold the same number and the same bump rule; bump both in the same commit. Adding an *optional* field is not a bump — an older peer ignores what it does not know.
- **A sibling expires `SiblingTTL` after its last `introduce`, and the TTL is mirrored too.** `SiblingTTL` (15s, `internal/protocols/siblings.go`) and `SIBLING_TTL_SECONDS` (`nodes/lib/core/siblings.py`) are the same behaviour expressed twice, so change them together — a Go service and a node disagreeing about when a peer is dead is a difference in *behaviour*, not in wire format, and nothing on the wire reveals it. Expiry is lazy (checked and applied on `Get`/`GetName`) on purpose: it needs no background sweep in five processes, and the question it answers — "is this peer still there?" — is only ever asked at dispatch.
- **The hub has no default JWT secret.** `--secret`/`JWT_SECRET` is empty by default and the hub then generates a random per-process secret with a warning (tokens do not survive a restart). Set it explicitly in any deployment.
- **The DASH control routes need `--dash-token`.** `POST`/`DELETE /stream` are behind `requireDashToken`; with no token configured only a loopback caller may register or delete a stream, so widening the bind address cannot silently expose them.
- **Never install `gst-python-stubs` in the node venv.** It ships an overrides-only `Gst.pyi` at the same path as the real `PyGObject-stubs` file and silently clobbers it, which turns every GStreamer enum and constructor into an unknown-attribute error. See `./pyproject.toml`.
- **Analytics output is data, never a chart library's option object.** `nodes/lib/bustle/analytics.py` declares pipelines that emit generic chart data — an axis and values, a series of points — and `GET /nodes/analytics` returns them as a list of named queries. Mapping rows onto whatever renders them is the presentation layer's job, so no renderer's vocabulary may appear in a pipeline, a manifest or a handler reply (DESIGN invariant #8). The rule that enforces it lives in `nodes/tests/test_lib_bustle_analytics.py`, which checks the *keys* — a `$literal` expression renders as a value, so matching the rendered text would let the original stages back in.
- **A declared query returns one document, and its timestamps leave as strings.** Every bustle query ends as a single `$facet` document because the executor caps a result at 2000 documents and 1 MiB (appending `$limit` to the pipeline), so a query that returned one document per bucket would silently truncate on a long window and would cost a pass over the collection per chart. `$facet` nesting is capped at 2, which is why the views are siblings inside one facet rather than facets inside facets. And the service marshals documents as **relaxed extended JSON**, so a BSON date reaches a client as `{"$date": ...}` — an object no chart can label an axis with; `_iso()` wraps every emitted timestamp in `$dateToString`, and `$dayOfWeek`'s 1..7 is renamed to `Sun`..`Sat`. Grouping still happens on the real date, so ordering is unaffected. A shape-only unit test cannot see this defect — the field is present and non-empty either way — so `nodes/tests/test_lib_bustle_analytics.py` asserts the label's JSON type is `string`.
- **A fleet query's membership comes from the caller, and its collection is injected after validation.** A declaration is scoped `node` (the default) or `fleet`; a fleet one is keyed by `(node_type, scope='fleet')` and owned by the node type, so the last declaring node of that type replaces it whole while a node that declares none leaves it alone. `analytics.query` carries the caller's own node ids; the service intersects them with the type's declarations (`SelectFleetCollections`) to get the member collections and prepends one `$unionWith` per member beyond the first. Two rules follow and neither is negotiable: `$unionWith` stays **out** of the manifest allowlist (it is injected after `pipelineChecker` has run, so no manifest can name a collection it does not own), and the hub sends the fleet set with *every* query rather than classifying them, because a hub that had to recognise a fleet query would have to know a node's query names. No member is `models.ErrEmptyFleet`, never an empty report — empty arrays read as "the deployment saw nothing".
- **The analytics endpoint runs whatever a node declared, so no query name belongs in the hub.** `GetAnalytics` (`hub/internal/adapter/rabbitmq/nodes.go`) asks `analytics.queries.list`, then runs each declared query with the parameters *that query's* schema declares — sending `unit_time` to a query that does not take it is a payload error, and withholding it from one that does is a missing parameter. A query asking for something the endpoint cannot supply is reported per query rather than failing the report; the whole request fails only when nothing could be answered, because a 200 with an empty report reads like a node that has never seen anything.

## Testing

`make lint`, `make test` and `make typecheck` are the gates — run `make` before committing. Go coverage is narrow and deliberate: the RPC reply layer and the restart backoff (`internal/protocols/handlers_test.go`, `internal/backoff/backoff_test.go`), the sibling wire shape, the revision warning and the expiry of a peer that stopped introducing (`internal/protocols/siblings_test.go`, `internal/protocols/rabbitmq/router_test.go`), the tx codec preference lists and the shutdown verdict (`tx/internal/core/coder/element_test.go`, `tx/cmd/tx/main_test.go`), the hub's SQLite user store and signup validation (`hub/internal/db/sqlite/user_test.go`, `hub/internal/protocols/http/handlers/users_test.go`), the user model's serialization (`internal/models/user_test.go`), the rx data plane (`rx/internal/protocols/srt/broadcast_test.go`, `rx/internal/protocols/srt/pending_test.go`, `rx/internal/adapter/rabbitmq/nodes_test.go`, `rx/cmd/rx/cmdline_test.go`), the hub's subscription adapter and add-subscription validation (`hub/internal/adapter/rabbitmq/subscription_test.go`, `hub/internal/protocols/http/handlers/subscriptions_test.go`), the subscriptions store's duplicate-node translation (`subscriptions/internal/db/sqlite/subscription_test.go`), the analytics service's declaration store, usecase and both handler packages, and the hub's analytics adapter with its window arithmetic and per-query parameter selection (`hub/internal/adapter/rabbitmq/nodes_test.go`), plus the handler packages, whose tests enumerate the commands their service advertises and fail when one has no case, so adding a handler without a test breaks `make test`. Python coverage is `nodes/tests/` (stdlib `unittest`, no pytest) over the `nodes/lib/core` runtime: wire shapes, the router's delivery/ack/abandoned-trackID paths, the RPC retry ladder, sibling expiry against an injected clock, the node runtime's shutdown ordering and registration paths, the ticker, logging setup, version discovery, and the GStreamer frame path, and the query manifest the bustle node publishes — every stage against the service's allowlist, the placeholders against the declared schemas in both directions, the stage count and `$facet` depth against the executor's caps (counted through the nesting, not at the top level), the absence of any renderer's keys, and the report shape of each query (a facet view spliced into the report root instead of nested under its own key is a defect the unit tests catch and a live run shows as stray top-level fields); the GStreamer-dependent classes skip themselves where the bindings are absent. What no test covers is the wiring rather than the logic: no test drives a real SRT socket or a real GStreamer pipeline, because doing so needs a source, a codec and a peer, which is a deployment rather than a fixture. `./smoke.sh` is that run — the only thing in the repository that asserts against a *running* system — so when you change a flag, a port, a startup order or a shutdown path, it is what catches the break.
